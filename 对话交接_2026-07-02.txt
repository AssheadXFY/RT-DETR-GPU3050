3. J 方案原理（供新对话快速理解）
----------------------------------------------------------------------

问题: RT-DETR 的 O2O Hungarian 匹配 → 每个 GT 只有 1 个正样本 query
     → 300 query 中大量负样本 → 监督稀疏

J 的机制:
  训练时:
    1. topk 选出 300 query（encoder 输出）
    2. 复制成 K=2 组，content embedding 加高斯噪声 (σ=0.1)
    3. 300 → 600 query 进 decoder，每组独立做 Hungarian match
    4. 每 GT 匹配 2 个 query（vs baseline 1 个）
  推理时: 只用 300 query，K 组输出取平均 → 零额外开销

J vs RT-DETRv3 的关系:
  RT-DETRv3 = CNN aux head + Query Perturbation + O2M decoder
  J = 只提取了 Query Perturbation 这一个组件
  NOT 一模一样，是 RT-DETRv3 的最小核心子集

4. J+L 论文框架
----------------------------------------------------------------------

标题方向: "Training Optimization for Lightweight DETR via Query Diversification and Self-Distillation"

组件:
  J - Query Perturbation (来源: 摘取自 RT-DETRv3 的 Query Perturbation 组件)
    原理: K 组 query 复制 + 高斯噪声 → 密集监督
    改动: rtdetrv2_decoder.py (~40行)

  L - Denoising Self-Distillation [原创]
    原理: KL loss — 常规 query 的 class logit 模仿同 GT 的 denoising query 预测分布
          denoising query 知道自己的 GT 身份，其解码输出是高质量软标签
    改动: rtdetrv2_criterion.py (loss_labels_kd 方法, ~50行)
    KD 配置: loss_kd weight=0.5, kd_temperature=2.0

消融路径:
  Baseline → +J → +L → 最终
  可选升级: J2 (Fourier 域扰动替代高斯噪声，保留空间结构)

代码状态: J 和 L 都已经写好了，criterion 和 decoder 有完整实现。
  J+L 的 config: rtdetrv2_r18vd_120e_coco_queryperturb_kd.yml
