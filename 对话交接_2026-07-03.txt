1. 2026-07-03 核心进展
----------------------------------------------------------------------

=== 今日已完成的实验 ===

1a) J+L (KD self-distillation) smoke test — 失败
    epoch 0 mAP = 14.56% (vs J-only 15.43%, -0.87%)
    死因: denoising query 在 epoch 0 的预测是随机分布，用垃圾做 teacher → 反向污染

1b) J+Consistency smoke test — 失败
    epoch 0~2: 15.70%, 24.80%, 28.21% — 全程与 J-only 持平
    死因: VFL loss 已经把 K 组 query 拉向同一个 GT，consistency loss 是冗余信号

1c) J2 (Fourier 域扰动) — 未跑，用户评估后否决
    死因: FFT 在 content embedding 上无理据（256d learnable vector 没有频率语义）

1d) ECA backbone — 未跑，用户评估后否决
    死因: 单个 ECA 模块是 2020 年的东西，换位置放不构成方法论贡献

1e) J+ISFE smoke test — 通过
    epoch 0: 15.58% (+1.18 vs baseline, +0.15 vs J-only)
    epoch 1: 24.95% (+0.88 vs baseline, +0.11 vs J-only)
    持续正 delta，ISFE 不是零贡献

=== 正在进行中的实验 ===

1f) S1: CSCG+J smoke test (smoke_cscg_j.log, epoches=3)
    配置: rtdetrv2_r18vd_120e_coco_cscg.yml
    CSCG = Cross-Scale Context Gate：C5→C3/C4 通道门控跨层上下文传播

1g) S2: ISFE-only smoke test (smoke_isfe_only.log, epoches=3)

3. 论文方法论（2026-07-03 确立）
----------------------------------------------------------------------

用户明确了论文创新的五步路径：

  Step 1: 找一篇最新的开源顶会论文作为 baseline，跑通代码，复现结果
  Step 2: 拆解 baseline 的模块，理解每个模块的作用
  Step 3: 在同期其它顶会论文中找到功能相似的模块，进行替换（缝合）
  Step 4: 替换后能跑出相当或更好的结果 → 写论文。
         写作要隐藏"替换操作"，按 baseline 的叙事逻辑分析领域问题
  Step 5: 如果能对模块做领域适配（不是原样搬过来），故事更完整

关键原则：单个已有模块不算创新。多个模块的缝合组合 + 特定的协同机制 +
针对 RT-DETR 具体缺口的设计理由 = 可以。不局限于两个模块。

4. 当前论文框架：J + Encoder Enhancement
----------------------------------------------------------------------

叙事方向: "轻量 DETR 在 encoder 和 decoder 两侧存在不对称瓶颈"

  Decoder 侧 — J (Query Perturbation)
    解决: O2O matching 监督稀疏
    机制: 300 query × K=2 groups + Gaussian noise → 每 GT 匹配 2 query
    改动: rtdetrv2_decoder.py

  Encoder 侧 — 两条候选路线（并行验证中）
    ISFE: intra-scale — C3/C4 各自增强容量（inverted bottleneck + DWConv）
    CSCG: cross-scale — C5 transformer 上下文传播到 C3/C4（通道门控）

  最终方案: J + (ISFE 和/或 CSCG)，具体取决于烟雾测试结果

  行1: RT-DETRv2-S official = 48.1%
  行2: RT-DETRv2-S our reproduction = 47.74%
  行3: RT-DETRv2-S + Ours = X%

8. CLAUDE.md 关键规则
----------------------------------------------------------------------

提方案前必须通过 六问：
  1. 机制在 RT-DETR 上下文里成立吗？
  2. 已有机制在提供等价信号吗？（冗余检查）
  3. 多个模块组合是否产生新知？（缝合检查）
  4. 架构有什么具体阻碍？
  5. 失败时第一个调试信号是什么？
  6. 验证周期多长？

技术原则:
  - 优先在 encoder 层面找机会（未被 10 条梯度路径饱和）
  - 优先改变特征本身或信号结构
  - 提方案时必须同时回答"它最容易怎么死"
